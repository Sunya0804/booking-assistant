# booking_assistant

NOL 티켓(구 인터파크 티켓) 오픈 시간에 맞춰 **예매창을 정확한 순간에 열어주는** 도우미.

- NOL 서버 시계를 HTTP `Date` 헤더로 측정해 내 PC와의 오차를 ms 단위로 보정
- 실제 Chrome 창(로그인 유지되는 전용 프로필)으로 공연 페이지를 띄워둠
- 오픈 10초 전부터 `예매하기` 버튼 상태를 감시 → 활성화되는 즉시 클릭 → 알림음
  - 버튼이 이미 열려 있으면(재오픈 공연 등) 정각에 클릭
  - 오픈 후에도 안 열리면 그때만 새로고침
  - NOL처럼 버튼은 눌리는데 옆에 "오픈 예정" 문구만 있는 경우: 문구가 사라지거나 정각이 되면 클릭
  - 너무 일찍 눌러 "오픈 전" 알림/팝업이 뜨면 닫고 바로 다시 클릭 (오픈 후 20초까지)
- 그 뒤 대기열, 보안문자, 좌석 선택, 결제는 **직접** 진행

> 보안문자 우회나 좌석·결제 자동화는 넣지 않았습니다. NOL 약관 위반으로 계정 정지될 수 있고,
> 매크로로 산 표를 되파는 건 공연법상 처벌 대상입니다. 이 도구는 "정시에 정확히 누르기"까지만 합니다.

## 프로그램으로 실행 (추천)

[Releases](https://github.com/Sunya0804/booking-assistant/releases/latest)에서 `NOL-booking-assistant-x.y.z.exe`를 받아 아무 폴더에 두고 더블클릭하면 됩니다. 파이썬이 없는 PC에서도 동작합니다 (Chrome만 있으면 됨).

- 처음 실행할 때 "Windows의 PC 보호" 창이 뜨면 **추가 정보 → 실행**을 누릅니다. 코드 서명 인증서가 없어서 나오는 경고입니다.
- 켤 때와 켜 둔 동안 6시간마다 새 버전을 확인해 받아 두고, 설치하고 다시 시작할지 묻습니다. 예매가 진행 중일 때는 묻지 않고 끝난 뒤에 묻습니다. 진행 기록 오른쪽 위에서 버전을 보고 직접 확인할 수도 있습니다.

1. 창 위쪽에 NOL 서버 시각이 표시됩니다. 오른쪽 위 버튼으로 라이트/다크 테마를 바꿀 수 있습니다(처음엔 Windows 설정을 따름). 처음 켤 때 자동으로 측정합니다.
2. 공연 페이지 주소, 오픈 날짜, 오픈 시각을 입력합니다. 날짜는 `20261020`·`1020`, 시각은 `200000`·`2000`처럼 숫자만 써도 칸을 벗어나면 `2026-10-20`, `20:00:00`으로 바뀝니다. 한 페이지에 예매하기 버튼이 여러 개라면(야구 포스트시즌처럼 경기별 버튼) **경기/회차 키워드**에 카드에 적힌 글자를 넣습니다. 예: `3차전`, `10월 21일`. 여러 단어는 모두 포함된 카드를 고릅니다. 입력값은 다음 실행 때 그대로 남아 있습니다.
3. 오픈 **5분 전**에 `시작`을 누릅니다. Chrome을 처음 띄울 때 20초 넘게 걸릴 수 있습니다.
4. 열린 Chrome 창에서 로그인하고 날짜/회차를 골라둡니다.
5. 버튼이 열리는 순간 자동으로 눌러줍니다. 삐 소리가 나면 직접 진행합니다.

## 안드로이드 폰에서 실행

휴대폰에서 [Releases](https://github.com/Sunya0804/booking-assistant/releases/latest)의 `NOL-booking-assistant-x.y.z.apk`를 받아 엽니다. Android 11 이상.

- 처음 설치할 때 "출처를 알 수 없는 앱" 설치를 허용하라고 나오면 허용합니다(브라우저나 파일 앱에 한 번).
- 입력 화면을 열 때와, 6시간이 지나 입력 화면으로 돌아올 때 새 버전을 확인합니다. 새 버전이 있으면 받아 두고 설치할지 묻습니다. 예매 화면에 있는 동안에는 묻지 않습니다. 처음 한 번은 NOL 예매도우미에 "이 출처의 앱 설치"를 허용해야 합니다. 입력 화면 맨 아래 `업데이트 확인`으로 직접 확인할 수도 있습니다.

앱 안에 브라우저 화면을 띄워 PC 버전과 같은 방식으로 동작합니다. 서버 시간 보정, 버튼 감시, "오픈 예정" 처리, 너무 일찍 눌렀을 때 다시 누르기, 안 열리면 새로고침이 모두 같습니다. 버튼은 화면에 실제 터치를 보내 누르므로 손가락으로 누른 것과 똑같이 처리됩니다.

1. `브라우저 열기`로 들어가 NOL에 로그인해 둡니다. Chrome과 로그인이 따로라서 앱에서 한 번 해야 하고, 그 뒤로는 유지됩니다.
   같은 화면에서 공연 페이지로 이동한 뒤 위쪽 `이 주소로 설정`을 누르면 그 주소가 공연 페이지 주소 칸에 들어갑니다.
2. 오픈 날짜/시각, 필요하면 경기/회차 키워드를 넣고 오픈 **5분 전**에 `시작`을 누릅니다.
3. 열린 화면에서 날짜/회차를 골라 둡니다. 위쪽 막대에 서버 시각과 남은 시간이 보이고, 막대 글자를 누르면 기록이 펼쳐집니다.
4. 버튼이 열리는 순간 자동으로 누르고 소리와 진동으로 알려 줍니다. 그다음은 직접 진행합니다. 결제 앱으로 넘어가는 것도 그대로 됩니다.

앱이 화면을 켜진 상태로 유지하지만, 다른 앱으로 넘어가면 감시가 느려질 수 있으니 앱을 띄워 둔 채로 두세요. 모바일 NOL이 웹 예매를 막고 NOL 앱으로만 보내는 공연이라면 이 방식은 쓸 수 없습니다.

정시 알림음은 알림 볼륨을 따릅니다. 무음·진동 모드면 진동만 울립니다.

## 시간 맞추기와 누르기 (PC·안드로이드 공통)

- **기준 서버**: 인터파크 예매 서버(`poticket.interpark.com`, `ticket.interpark.com`), 입력한 공연 페이지의 서버, `tickets.interpark.com`의 시계를 한꺼번에 재고 오차가 가장 작은 곳을 씁니다. 서버들의 시계는 서로 같지만, 응답이 빠른 예매 서버가 보통 3~4배 정확합니다(오차 ±30 ms 안팎). 서버 시각 아래에 어느 서버를 썼는지 나옵니다.
- **미리 누르기** (선택): 켜면 요청이 서버에 닿는 시간(왕복의 절반)에서 측정 오차를 뺀 만큼, 최대 150 ms 일찍 누릅니다. 서버에 너무 일찍 닿으면 "오픈 전"으로 거절되어 오히려 늦어지므로 넉넉히 덜 당깁니다.
- **무시된 클릭 다시 누르기**: 누른 뒤 0.25초 안에 페이지가 서버로 아무 요청도 보내지 않으면, 사이트가 아직 안 열렸다고 보고 버튼을 무시한 것이므로 곧바로 다시 누릅니다. 요청이 나갔는데 화면이 안 바뀌면(서버가 느린 경우) 중복 예매를 피하려고 다시 누르지 않습니다.
- **기록 파일**: 실행할 때마다 기록을 파일로 남깁니다. 줄마다 내 기기 시각과 서버 시각이 ms까지 찍혀 있어, 몇 ms에 눌렀는지 나중에 확인할 수 있습니다.
  - PC: `%USERPROFILE%\.booking_assistant\logs\` (창 아래 `기록 폴더`)
  - 안드로이드: 예매 화면 위쪽 막대의 `기록 공유`로 메모·메신저·메일에 보냅니다.
  - 최근 30개만 남깁니다.
  - 누른 뒤 10초 동안 페이지가 보낸 요청(`→`)과 받은 응답(`←`)의 주소도 남깁니다(주소 뒤 `?…` 부분은 빼고). 예매·대기열이 어느 서버로 가는지 알 수 있습니다.
  - 오픈 1분 전 사이트 쿠키의 **이름**을 남깁니다(값은 남기지 않음).
- **로그인 확인**: 오픈 1분 전에 로그인 쿠키가 보이지 않으면 소리·진동과 함께 경고합니다. NOL의 로그인 쿠키 이름을 아직 몰라 이름으로 짐작하는 방식이라, 로그인했는데도 경고가 뜰 수 있습니다. 그런 기록을 받으면 맞는 이름으로 고칩니다.
- **연결 속도**: 서버 시각 아래에 연결 종류(와이파이/모바일 데이터)와 왕복 시간, 빠름(40 ms 이하)·보통·느림이 나옵니다. 오픈 전에 연결을 바꿔 가며 `다시 측정`해 보고 빠른 쪽으로 예매하세요.

### 예행연습

진짜 오픈 전에 한 번 해 보세요. NOL이 실제로 어떻게 동작하는지 기록에 남습니다.

1. 지금 예매가 열려 있는 아무 공연 페이지를 고릅니다.
2. 오픈 시각을 2분쯤 뒤로 넣고 `시작`합니다. 로그인하고 날짜/회차를 골라 둡니다.
3. 정각에 앱이 버튼을 누르고 예매·대기열 화면이 뜨면, 좌석을 고르지 말고 닫습니다.
4. 기록 파일(폰은 `기록 공유`)을 확인하거나 보내 주세요. 다음을 알 수 있습니다.
   - 누르자마자 어느 서버로 무슨 요청이 갔는지
   - 무시된 클릭 감지가 NOL에서 통하는지
   - 로그인 쿠키 이름

## 명령줄로 실행

### 설치

```
pip install -r requirements.txt
```

PC에 Chrome이 설치되어 있어야 합니다 (Playwright가 설치된 Chrome을 사용).

## 사용법

서버 시각 확인:

```
python main.py time
```

오픈 시각에 예매창 열기:

```
python main.py run --url "https://tickets.interpark.com/goods/XXXXXXXX" --open "2026-10-20 20:00:00"
```

1. 처음 실행하면 전용 Chrome 창이 열립니다. 로그인해 두면 다음부터 유지됩니다 (`~/.booking_assistant/chrome-profile`).
2. 오픈 전에 날짜/회차를 미리 골라두세요.
3. 새로고침 없이 버튼이 열리는 순간 클릭하고, 삐 소리가 나면 직접 진행합니다.

| 옵션 | 기본값 | 설명 |
|---|---|---|
| `--match` | 없음 | 예매 버튼이 여러 개일 때 경기/회차 키워드 (예: `--match 3차전`) |
| `--label` | `예매하기` | 버튼 문구가 다를 때 지정 (여러 번 가능) |
| `--reload-after` | `2.0` | 오픈 후 버튼이 몇 초간 안 열리면 새로고침할지 |
| `--early` | 꺼짐 | 요청이 서버에 닿는 시간만큼 미리 누르기 |
| `--give-up-after` | `20` | 오픈 후 몇 초까지 시도할지 |
| `--time-url` | 자동 | 서버 시간을 잴 주소 (기본: 예매 서버와 공연 페이지 중 가장 정확한 곳) |

## 새 버전 내기

1. `booking_assistant/__init__.py`의 `__version__`을 올립니다 (예: `0.2.1`). PC exe와 안드로이드 앱이 이 버전 하나를 함께 씁니다.
2. 바뀐 코드를 커밋하고 push합니다.
3. 아래를 실행하면 exe와 APK를 만들어 GitHub 릴리스 `v0.2.1`로 올립니다. 노트는 업데이트할지 묻는 창에 나옵니다.

```
pip install pyinstaller
python release.py "바뀐 점"
```

`python release.py --build-only`는 `dist/`에 만들기만 합니다. 설치된 프로그램과 앱은 최신 릴리스 하나만 보고 곧바로 그 버전으로 올라갑니다. GitHub이 파일 이름의 한글을 지우기 때문에 릴리스 파일 이름은 영문입니다.

APK 빌드에는 Android SDK(`android/local.properties`의 `sdk.dir`, git 제외)와 JDK 17 이상이 필요합니다. Windows 사용자 폴더 이름이 한글이면 에뮬레이터가 동작하지 않으므로 SDK는 `C:\Android\Sdk`처럼 영문 경로에 둡니다.

APK 서명 키는 사용자 폴더의 `.booking_assistant/`(`android-release.jks`, `android-signing.properties`)에 있습니다. 업데이트는 같은 키로 서명한 APK만 설치되므로 **이 두 파일을 꼭 따로 백업**하세요. 잃어버리면 휴대폰에서 앱을 지우고 새로 설치해야 합니다.
